 Plan API Endpoints and Parameters Guide Angular Frontend Integration Reference IWMS Plan Module Base route /api/IwmsWeb Version 1.0 1 October 2026 This guide documents the Plan API exposed by the RdWeb project for Angular clients. It identifies all 12 endpoints, their access rules, request formats, required parameters, conditional validation, PDF restrictions, and representative requests. The frontend must send the internal JWT on every call and must use the RdWeb host rather than the iwms_api host. 1 Common API Requirements Item Requirement Host RdWeb project host Base route {RDWEB_BASE_URL}/api/IwmsWeb Authorization Bearer JWT using the Api policy Token type TokenType claim must be Internal Antiforgery Not required because the controller uses IgnoreAntiforgeryToken JSON content type application/json Upload content type multipart/form-data; browser must set the boundary Date format dd/MM/yyyy Maximum PDF size 5 MB Required JWT Claims Claim Required value or purpose TokenType Internal. Required by the Api authorization policy. UserId Used for CreatedBy, UpdatedBy, forwarding, approval and rejection audit data. DistrictCode Controls district ownership. Value 0 identifies a state-level user. District access rule: a district user can access only the district in the token. A state-level user with DistrictCode 0 can act across districts where the endpoint permits it. 2 Endpoint Summary No Method Route Format Purpose 1 POST /GetWorkListofPlan JSON List plans by scheme, year and district 2 POST /SavePlanDetails JSON Create or update a plan 3 GET /DownloadPdfPlan Query Download authenticated district PDF 4 GET /ViewDownloadPdfPlan Query Download a specified district PDF 5 GET /DownloadPdfPlanState Query Download state-approved PDF 6 POST /SavePlanFileandForward Multipart Upload district PDF and forward 7 POST /ApprovePlanandUploadFile Multipart State approval for one plan 8 POST /ApprovePlanandUploadFileMultiple Multipart State approval for multiple plans 9 POST /RejectPlan JSON Reject a plan at state level 10 POST /RevertPlan JSON Revert a plan 11 GET /BudgetTypeList None Get budget type master 12 POST /GetApprovedPlanListOfWork JSON Get approved plan or work list 3 Plan Listing and Maintenance 3.1 POST /GetWorkListofPlan Returns plans matching the supplied scheme, financial year and district filters. Access: authenticated internal users. A district user's token district overrides the body value. A state user may request another district. Parameter Type Required Description schemeCode integer Yes Scheme identifier. Must be greater than zero. finYr string Yes Financial year, for example 2026-27. districtCode string Yes District to query. Required by GetWorkListRequest. POST /api/IwmsWeb/GetWorkListofPlan { "schemeCode": 5, "finYr": "2026-27", "districtCode": "12" } Success response: HTTP 200 with success, count and data array. Missing or invalid fields return the automatic HTTP 400 validation response. 3.2 POST /SavePlanDetails Creates a new plan when id is zero and updates an existing plan when id is greater than zero. Access: authenticated internal users. UserId and DistrictCode claims are required. Current validation note: the action binds mdlPlan. If DistrictCode is a non-nullable or Required property in mdlPlan, include districtCode in the JSON even though the API replaces it with the token value during create. Parameter Type Required Description id integer Yes 0 creates; a positive value updates. districtCode string Current model Include when mdlPlan validation requires it. Token value controls create ownership. finYr string Yes Financial year, such as 2026-27. workName string Yes Name or description of the work. workType string Yes Valid work type code from the UI/master. sectorArea string Yes R for rural; the non-rural value follows the existing model. schemeCode integer Yes Scheme identifier. workCategory string/code Yes Selected work category. workSubCategory string/code As applicable Selected work subcategory. constCode string Yes Constituency code. assemblyNo integer As applicable Assembly number. priority integer As applicable Plan priority. dlcApprovalDate1 string date District Required for district plans; dd/MM/yyyy. blockApprovalDate1 string date District Required for district plans; dd/MM/yyyy. slcApprovalDate1 string date State Required for state plans; dd/MM/yyyy. SavePlanDetails Location and Financial Fields Parameter Type Required Description blockCode string Rural Block code when sectorArea is R. panchayatCode string Rural Panchayat code when sectorArea is R. villageCode string Rural Village code when sectorArea is R. townCode string Urban Town code when sectorArea is not R. departmentId integer As applicable Executing department identifier. agencyId integer As applicable Executing agency identifier. budgetType integer State/as applicable Budget type identifier. schemeAmount decimal Yes Amount funded by the primary scheme. isConvergence boolean Yes True when another scheme contributes. convergenceSchemeCode integer If convergence Contributing scheme identifier. convergenceAmount decimal If convergence Amount contributed by convergence scheme. cmBadpCategoryCode code Optional CM or BADP category code. jayShreeCode code Optional Jay Shree code, when applicable. District Plan Example { "id": 0, "districtCode": "12", "finYr": "2026-27", "workType": "N", "sectorArea": "R", "dlcApprovalDate1": "01/10/2026", "blockApprovalDate1": "01/10/2026", "schemeCode": 5, "workCategory": "01", "workSubCategory": "0101", "blockCode": "001", "panchayatCode": "0001", "villageCode": "000001", "departmentId": 1, "agencyId": 1, "schemeAmount": 1000000.00, "isConvergence": false, "workName": "Construction of community hall", "assemblyNo": 16, "constCode": "001" } State Plan Differences Use slcApprovalDate1 instead of the two district approval dates. The token DistrictCode must be 0. The API sets PlanType to S, sets forwarding fields, and obtains the SSO ID server-side. For district users, the API sets PlanType to D. Do not send CreatedBy, UpdatedBy, ForwardedBy, ForwardToStateDate or ProposedAmount as trusted values. Amount calculation: when isConvergence is true, ProposedAmount equals SchemeAmount plus ConvergenceAmount. Otherwise ProposedAmount equals SchemeAmount. 4 PDF Download Endpoints 4.1 GET /DownloadPdfPlan Downloads the district plan PDF belonging to the authenticated district. Query parameter Type Required Description finYear string Yes Financial year, for example 2026-27. schemeCode integer Yes Scheme identifier. GET /api/IwmsWeb/DownloadPdfPlan?finYear=2026-27&amp;schemeCode=5 DistrictCode is taken from the token. Success returns application/pdf. No matching file returns HTTP 404. 4.2 GET /ViewDownloadPdfPlan Downloads a district plan PDF for an explicitly supplied district. Query parameter Type Required Description districtCode string Yes District whose PDF is requested. finYear string Yes Financial year. schemeCode integer Yes Scheme identifier. GET /api/IwmsWeb/ViewDownloadPdfPlan?districtCode=12&amp;finYear=2026-27&amp;schemeCode=5 A district user may request only its own district. A state-level user may request any district. 4.3 GET /DownloadPdfPlanState Downloads the state-approved PDF for a specified district, year and scheme. Query parameter Type Required Description districtCode string Yes District whose state-approved PDF is requested. finYear string Yes Financial year. schemeCode integer Yes Scheme identifier. GET /api/IwmsWeb/DownloadPdfPlanState?districtCode=12&amp;finYear=2026-27&amp;schemeCode=5 The same district-access validation used by ViewDownloadPdfPlan applies. 5 PDF Upload and Forwarding Endpoints All upload endpoints require multipart/form-data. Do not manually set the Content-Type header in Angular; HttpClient must generate the multipart boundary. 5.1 POST /SavePlanFileandForward Uploads a district plan PDF and forwards the plan to the state level. Form field Type Required Description file PDF file Yes Valid PDF, maximum 5 MB. schemeCode integer Yes Scheme identifier expected by mdlPlanFile. finYr string Yes Financial year expected by mdlPlanFile. UserId and DistrictCode are assigned from the token. The controller validates the .pdf extension, application/pdf MIME type and %PDF- file signature. const form = new FormData(); form.append('file', pdfFile, pdfFile.name); form.append('schemeCode', '5'); form.append('finYr', '2026-27'); 5.2 POST /ApprovePlanandUploadFile Approves one district plan at state level and uploads the state PDF. Access: state-level users only. The token DistrictCode must equal 0. Form field Type Required Description file PDF file Yes Valid PDF, maximum 5 MB. schemeCode integer Yes Scheme identifier. finYr string Yes Financial year. districtCode string Yes District whose plan is being approved. const form = new FormData(); form.append('file', pdfFile, pdfFile.name); form.append('schemeCode', '5'); form.append('finYr', '2026-27'); form.append('districtCode', '12'); 5.3 POST /ApprovePlanandUploadFileMultiple Approves multiple selected plans at state level using one uploaded state PDF. Access: state-level users only. The token DistrictCode must equal 0. Form field Type Required Description file PDF file Yes Valid PDF, maximum 5 MB. plans JSON string Yes A non-empty JSON array matching List&lt;SelectedPlan&gt;. const form = new FormData(); form.append('file', pdfFile, pdfFile.name); form.append('plans', JSON.stringify(selectedPlans)); SelectedPlan model dependency: the attached controller does not define SelectedPlan. The Angular object keys must exactly match the C# SelectedPlan properties. Typical identifying values are districtCode, schemeCode and finYr, but the frontend team must copy the authoritative model definition before final binding. 6 Decision and Master Endpoints 6.1 POST /RejectPlan Rejects a plan through the existing IPlan repository. Access: state-level users only. The token DistrictCode must equal 0. The API adds CreatedBy and CreatedBySsoId. Body field Type Required Description schemeCode integer Model-dependent Scheme identifier used by mdlPlanFile. finYr string Model-dependent Financial year. districtCode string Model-dependent District whose plan is rejected. rejection field string Business-dependent Use the exact rejection reason or remarks property declared by mdlPlanFile. POST /api/IwmsWeb/RejectPlan { "schemeCode": 5, "finYr": "2026-27", "districtCode": "12" } Add any mandatory rejection-reason field defined in mdlPlanFile. The controller source alone does not expose its property name. 6.2 POST /RevertPlan Reverts a plan through the existing IPlan repository. Access: any authenticated internal user. The API adds CreatedBy from the token. Body field Type Required Description schemeCode integer Model-dependent Scheme identifier used by mdlPlanFile. finYr string Model-dependent Financial year. districtCode string Model-dependent District associated with the plan. reason string Business-dependent Use the exact remarks/reason property declared by mdlPlanFile. POST /api/IwmsWeb/RevertPlan { "schemeCode": 5, "finYr": "2026-27", "districtCode": "12" } 6.3 GET /BudgetTypeList Returns the complete MstPlanBudgetType master list. Request parameters: none. Authentication is still required. GET /api/IwmsWeb/BudgetTypeList Success response: HTTP 200 with success, count and data array. 6.4 POST /GetApprovedPlanListOfWork Returns approved plan/work records using the existing mdlPlan filters and configured hexKey. Body field Type Required Description schemeCode integer Typical filter Scheme identifier. finYr string Typical filter Financial year. districtCode string Typical filter District filter when required by repository logic. POST /api/IwmsWeb/GetApprovedPlanListOfWork { "schemeCode": 5, "finYr": "2026-27", "districtCode": "12" } Server dependency: the application configuration must contain hexKey. If missing, the API returns HTTP 500. 7 Response and Error Handling Status Meaning Frontend action 200 Request completed Use data/count or display message. 400 Validation, missing date, invalid JSON, invalid PDF, or missing SSO ID Display the response message or ValidationProblemDetails errors. 401 Missing, expired or invalid token/claim Clear session and require login. 403 Wrong district or state-only operation Show an authorization message. 404 Plan or PDF not found Show a not-found message. 413 Upload exceeds request limit Ask the user to upload a smaller PDF. 500 Missing configuration or unexpected server/database error Log the trace and show a generic error. Automatic Validation Response { "title": "One or more validation errors occurred.", "status": 400, "errors": { "DistrictCode": ["The DistrictCode field is required."] }, "traceId": "..." } This response occurs before the controller method runs. The Angular request must include the missing field, or the API should use an endpoint-specific DTO with nullable server-controlled fields. 8 Angular Integration Checklist Point the Plan service to the RdWeb host and /api/IwmsWeb base route. Attach Authorization: Bearer &lt;token&gt; through one HTTP interceptor. Send districtCode in GetWorkListofPlan because GetWorkListRequest explicitly requires it. For SavePlanDetails, send id 0 for create and a positive id for update. Include districtCode in SavePlanDetails while the current mdlPlan validation requires it. Send dates as dd/MM/yyyy. Use responseType blob for all PDF download endpoints. Use FormData for upload endpoints and never manually set multipart Content-Type. Validate PDF extension, size and type before upload; the server independently verifies all three plus the PDF signature. Copy the complete mdlPlan, mdlPlanFile and SelectedPlan C# property sets into Angular interfaces before final release. Do not trust or send audit fields that the server derives from JWT claims. Handle ValidationProblemDetails errors as well as the API's success/message/data response shape. 9 Model Definitions Needed for Final Contract The controller source provides exact endpoint and transport contracts, but the complete payload contract for several endpoints is owned by models outside the supplied file. To finalize the API document without any model-dependent placeholders, add the following C# classes as an appendix or OpenAPI schema source: mdlPlan mdlPlanFile SelectedPlan MstPlanBudgetType Until those classes are included, treat this guide as authoritative for routes, HTTP methods, claims, access checks, explicitly referenced parameters, dates and file rules; treat fields labelled model-dependent as provisional.
